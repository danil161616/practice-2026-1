# Структура git-репозитория проекта «Робокрафт»

Следует придерживаться предложенной структуры git-репозитория. В нашем проекте структура была расширена для соответствия требованиям базового и вариативного заданий.

## Файловая структура git-репозитория

```plaintext
/
├── README.md
├── docs/
│   ├── about.md
│   ├── journal.md
│   ├── partner_report.md
│   └── telegram_bot_tutorial.md
├── reports/
│   ├── README.md
│   ├── Отчет_Робокрафт.docx
│   ├── Отчет_Робокрафт.pdf
│   └── materials_for_report.md
├── site/
│   ├── index.html
│   ├── about.html
│   ├── bot_tutorial.html
│   ├── journal.html
│   ├── resources.html
│   ├── team.html
│   ├── css/
│   │   └── styles.css
│   └── assets/
│       └── images/
│           ├── 3d_printed_parts.jpg
│           ├── blender_model.png
│           ├── controller_render.png
│           ├── soldering.jpg
│           └── wiring_diagram.png
├── src/
│   ├── bot.py
│   └── requirements.txt
├── task/
│   ├── README.md
│   ├── git_structure.md
│   └── terms.md
└── .gitignore
```

## Описание структуры git-репозитория

1. **README.md**
   Файл, расположенный в корне репозитория, содержит основную информацию о проекте:
   - Наименование практики.
   - Период проведения.
   - Участники (ФИО).
   - ФИО ответственного по проектной (учебной) практике.
   - Наименование проекта по «Проектной деятельности».
   - ФИО куратора по проектной деятельности.
   - Формулировка задания вариативной части.
   Этот файл служит точкой входа для всех, кто работает с репозиторием.

2. **docs/**
   Папка для размещения документации по практике в формате Markdown:
   - **about.md** — детальное техническое описание разрабатываемой платформы «Робокрафт».
   - **journal.md** — журнал прогресса (таймлайн разработки) с датами и этапами.
   - **partner_report.md** — отчет о взаимодействии с организацией-партнером («Робостанция»).
   - **telegram_bot_tutorial.md** — подробное техническое руководство с UML-диаграммами по созданию Telegram-бота (Вариативная часть).

3. **reports/**
   Папка для хранения отчётов по практике:
   - **Отчет_Робокрафт.pdf** — итоговый детализированный отчёт о прохождении проектной практики (более 15 страниц).
   - **Отчет_Робокрафт.docx** — исходный файл отчета в формате Microsoft Word.
   - **materials_for_report.md** — вспомогательные материалы для заполнения шаблонов.
   - **README.md** — описание содержимого директории отчетов.

4. **site/**
   Папка для статического веб-сайта со всеми его ресурсами:
   - **index.html** — главная страница (аннотация проекта).
   - **about.html, bot_tutorial.html, journal.html, resources.html, team.html** — внутренние страницы сайта, презентующие все аспекты работы.
   - **css/styles.css** — единый файл каскадных таблиц стилей для визуального оформления.
   - **assets/images/** — директория, содержащая все графические материалы (скриншоты кода, модели Blender, электрические схемы, фотографии сборки), используемые на страницах сайта.

5. **src/**
   Папка для исходного кода, создаваемого в рамках вариативного задания:
   - **bot.py** — исходный код Telegram-бота «Робокрафт Монитор» (Python).
   - **requirements.txt** — список Python-библиотек (зависимостей), необходимых для запуска приложения (в частности, pyTelegramBotAPI).

6. **task/**
   Папка предназначена для хранения текста задания:
   - **README.md** — полный текст задания в формате Markdown из исходного шаблона.
   - **git_structure.md** — файл с описанием структуры репозитория.
   - **terms.md** — контрольные сроки.

7. **.gitignore**
   Файл в корне репозитория, используемый для исключения из коммитов временных файлов, кэшей Python (например, `__pycache__`) или других системных логов.

## Преимущества структуры

- **Чёткое разделение:** Каждая папка отвечает за свою задачу, что упрощает навигацию и управление проектом. Все элементы (README, задание, документация, отчёты, код, сайт) имеют свои места в репозитории.
- **Гибкость:** Структура позволила легко интегрировать вариативное задание (папка `src` и файл туториала в `docs`) без нарушения логики базового проекта веб-сайта (папка `site`).
